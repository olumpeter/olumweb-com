## Step 4: Redirect Authenticated Users from Login 🔐

### Step 4a: Open Login Route

- Open:

```bash
app/routes/login.tsx
```

### Step 4b: Understand the Existing Loader

- Your loader already looks like this:

```ts
export async function loader({ request }: Route.LoaderArgs) {
	const userId = await getCurrentUserId(request)

	if (!userId) {
		return null
	}

	return redirect('/')
}
```

### Step 4c: What This Actually Means

#### Important

```text
userId exists → user is authenticated
```

- This does **not** mean "user exists in database"
- It means:

  ```text
  Request → Session → userId → Authenticated
  ```

#### Step-by-step behavior

1. Request hits `/login`
2. Loader runs before UI renders
3. `getCurrentUserId(request)` checks session
4. If session exists → user is authenticated
5. Redirect to `/`
6. If no session → allow access to login page

#### Mental Model

```text
Request → Session → Authentication State → Decision → Redirect or Continue
```

#### Core Rule

```text
If user is authenticated → Redirect away from login page
```

#### What just happened?

- Before:

  ```text
  Authenticated user → sees login page
  ```

- After:

  ```text
  Authenticated user → redirected away immediately
  ```

> The system now respects authentication state before rendering

#### Why this matters

- The UI never renders unnecessarily
- The system behaves intentionally
- The user is guided forward

> Authenticated → No login page → Redirect

#### Important Distinction

- The system is not checking:

```text
Does this user exist in the database?
```

- The system is checking:

```text
Is this request associated with a session?
```

#### Why this matters

```text
Database → Identity storage
Session → Identity in use
```

> Authentication is about the session, not just the user record

## Step 5: Apply the Same Logic to Signup 🧾

- Open:

  ```text
  app/routes/signup.tsx
  ```

#### Reality

```text
Signup route → No loader exists
```

- Right now:

```text
Authenticated user → Can still access /signup
```

- This creates a problem:

> A user who already has an account can still see "Create Account"

### Step 5a: Add Required Imports

- At the top of your file, add:

```ts
import { redirect } from 'react-router'
import { getCurrentUserId } from '~/data/auth.server'
```

### Step 5b: Add a Loader

- Add this above your `action`:

```ts
export async function loader({ request }: Route.LoaderArgs) {
	const userId = await getCurrentUserId(request)

	if (userId) {
		return redirect('/')
	}

	return null
}
```

### Step 5c: What This Does

- When a request hits `/signup`:

  ```text
  Request → Session → Authentication State → Decision
  ```

- If authenticated:

  ```text
  Authenticated → Redirect → Home
  ```

- If not:

  ```text
  Unauthenticated → Allow signup page
  ```

#### Mental Model

```text
Authenticated → Already has identity → No signup → Redirect
```

#### What Just Changed?

- Before:

  ```text
  Authenticated user → sees signup page
  ```

- After:

  ```text
  Authenticated user → redirected away
  ```

> Signup now respects authentication state
