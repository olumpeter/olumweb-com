## Introduction 🧭

- In Lesson 22, the system learned how to:
  - move authenticated user loading into the root route
  - create shared authenticated application state
  - provide authenticated data through shared layouts
  - centralize authenticated application infrastructure

```text
Request
  → Root Loader
  → Authenticated User
  → Shared Route Data
  → Layout()
  → Child Routes
```

#### Important

```text
Authenticated user data now lives at the application root
```

#### But another architectural problem now exists.

#### The Problem

- Right now:
  - the root route loads authenticated users
  - the root route provides shared authenticated data
  - the layout understands authenticated state

#### But child routes still exist.

#### Example

```text
Home Route
Settings Route
Profile Route
Dashboard Route
```

#### Reality

```text
Child routes may eventually need authenticated user access
```

#### Example

```text
Profile Header
Account Settings
Sidebar Navigation
Dashboard Widgets
```

#### Problem

- Right now:
  - the root route owns authenticated data
  - child routes do not automatically receive direct access

#### Reality

```text
Shared authenticated data still needs a consumption mechanism
```

> Shared application state is only useful if other routes can access it

- We are still not building:
  - Redux
  - Zustand
  - React Context authentication systems
  - global state stores
  - client-side caching systems

- We are building:

```text
Route hierarchy data sharing
```

> This lesson is about accessing parent route data through route architecture.

## Step 1: Observe the Current User Loading Flow 🔍

- Open:

```text
app/routes/home.tsx
```

#### Current Loader

```ts
export async function loader({ request }: Route.LoaderArgs) {
	const userId = await requireUserId(request)

	const user = await requireUser(request)

	const messages = await prisma.message.findMany({
		where: { userId },
		orderBy: { createdAt: 'asc' },
	})

	let profile = await prisma.profile.findUnique({
		where: { userId },
	})

	if (!profile) {
		profile = await prisma.profile.create({
			data: {
				userId,
				isFollowing: false,
			},
		})
	}

	return { user, messages, profile }
}
```

#### Important

- Right now:
  - the root route loads authenticated users
  - the home route also loads authenticated users
  - authenticated user data exists in multiple places

#### Reality

```text
The same authenticated user is now being loaded twice
```

#### Problem

```text
Shared authenticated state is starting to duplicate itself
```

#### Example

```text
Root Route
  → user

Home Route
  → user
```

#### Reality

```text
The Home route still owns data that now belongs to the Root route
```

> Shared state should not require repeated loading

## Step 5: Introduce useRouteLoaderData() ⚡

- React Router provides:

```tsx
useRouteLoaderData()
```

#### Add Import

```tsx
import {
	useRouteLoaderData,
} from 'react-router'
```

#### Important

- Unlike:

```tsx
useLoaderData()
```

- `useRouteLoaderData()` can access:

```text
Data loaded by another route
```

#### Reality

```text
Child routes can read parent route data
```

#### Mental Model

```text

  → Current route

useRouteLoaderData()
  → Another route
```

> Route hierarchy can become data hierarchy
