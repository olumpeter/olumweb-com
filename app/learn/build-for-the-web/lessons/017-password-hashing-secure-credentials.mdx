## Step 2: Understand Password Hashing 🔒

- Hashing is a transformation.

#### Reality

```text
Password → Hash Function → Encrypted-looking output
```

- Example:

```text
password1234
```

- Becomes:

```text
$2b$10$L7f9Zs1rG2v8M4mL4x5lOe8s2Wf8Qx4nG9rYhV2aYx5fJ9kP2vM3S
```

#### Important

- Hashing is not encryption.
- Encryption can be reversed.
- Hashing should not be reversed.

#### Mental Model

```text
Password → One-way transformation
```

#### Why this matters

> The system should verify secrets without storing them visibly

## Step 4: Create Password Utilities ✍️

- Right now:

```tsx
Hashing logic → does not exist
```

- We need a reusable location.

### Step 4a: Create a Password Utility File

- Create:

```text
app/utils/password.server.ts
```

- Add:

```text
import bcrypt from 'bcryptjs'

export async function hashPassword(password: string) {
	return bcrypt.hash(password, 10)
}

export async function verifyPassword({
	password,
	hash,
}: {
	password: string
	hash: string
}) {
	return bcrypt.compare(password, hash)
}
```

#### What this does

- Creates reusable password utilities.

```text
Password → Utility → Hashing
```

#### What just happened?

- Before:

```text
Security logic scattered or missing
```

- After:

```text
Security logic centralized
```

#### Why this matters

> Password protection should live in one place

### Step 5b: Transform Password Before Storage

- Find this section in your action:

```text
const user = await createUser({
	name,
	email,
	password,
})
```

#### What this code is currently doing

```text
User submits password → Password is sent directly → Database stores it as-is
```

- This means the password remains readable.

#### What we want instead

```text
User submits password → Password is transformed (hashed) → Database stores hash
```

#### Replace the Code

- Update your logic to this:

```ts
const hashedPassword = await hashPassword(password)

const user = await createUser({
	name,
	email,
	password: hashedPassword,
})
```

#### Step-by-step explanation

1. The user submits a password (e.g. `password123`)
2. `hashPassword(password)` transforms it into a secure hash
3. The hash (not the original password) is stored in the database

```text
password123 → hashPassword → $2b$10$... → Database
```

#### Key Detail

- You are **not changing your database schema**
- You are only changing what gets stored in the `**password**` field

```text
Before → password field = raw password
After  → password field = hashed password
```

#### What this does

- Protects credentials before persistence

```text
Password → Hash → Database
```

#### What just happened?

- Before:

```text
Password stored directly
```

- After:

```text
Password transformed before storage
```

#### Why this matters

> Databases should store hashes, not secrets

## Step 8: Update Login Password Verification 🔎

- Important clarification:

```text
Password verification does NOT happen in auth.server.ts
```

- Your `auth.server.ts` file only handles:

```tsx
Session creation → login()
Session destruction → logout()
Session reading → getCurrentUserId()
```

- The actual password check happens inside:

```bash
app/routes/login.tsx
```

### Step 8a: Locate the Current Password Check

- Open:

```bash
app/routes/login.tsx
```

- Find this logic inside your action:

```tsx
if (user.password !== password) {
	return {
		error: 'Invalid email or password',
	}
}
```

#### What this does

```text
Submitted password === Stored password → allow login
```

#### The Problem

- This only works when passwords are stored as plain text.
- But in Lesson 17:

  ```text
  Passwords are now hashed
  ```

- So this comparison will always fail.

### Step 8b: Use Secure Password Verification

- Add this import at the top of `login.tsx`:

  ```tsx
  import { verifyPassword } from '~/utils/password.server'
  ```

- Replace the direct comparison with:

  ```tsx
  const isValidPassword = await verifyPassword({
    password,
    hash: user.password,
  })

  if (!isValidPassword) {
    return {
      error: 'Invalid email or password',
    }
  }
  ```

### Step 8c: What Just Changed

#### Before

```text
Raw password === stored password
```

#### After

```text
Raw password → compared against hash → result
```

#### Mental Model

```text
Login Input → verifyPassword → Hash comparison → Result
```

- The system does not "decode" the hash.
- Instead, it checks if the input produces the same hash pattern.

#### Why this matters

> Password verification must respect hashing

- You never compare raw passwords again
- You always compare using a hashing function

#### What just happened?

- Before:

  ```text
  Login depended on plain text comparison
  ```

- After:

  ```text
  Login uses secure hash verification
  ```

> Authentication now works with protected credentials
