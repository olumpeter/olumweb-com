## Introduction 🧭

- In Lesson 24, the system learned how to:
  - centralize authenticated user loading
  - create a reusable `useUser()` hook
  - hide route implementation details
  - reuse authenticated user access

```text
Root Loader
  → user

useUser()
  → user

Components
  → user
```

#### Important

```text
Authenticated user access is now reusable
```

#### But another application problem now appears.

#### The Problem

- Right now, every authenticated user interacts only with their own profile.

```text
User
  → Own Profile
```

#### Reality

```text
The application currently
serves individual users
```

#### But imagine the application grows.

```text
Peter

Jane

John

Mary

David

...

Thousands of users
```

#### Question

Who manages them?

#### Example

```text
Manage Users

Manage Messages

Manage Profiles
```

#### Problem

```text
Growing applications
need administrative tools
```

> Applications are not only used by users;
> they are also managed by administrators.

- We are still not building:
  - analytics dashboards
  - reporting systems
  - enterprise management software

- We are building:

```text
Our first Admin Dashboard
```

> This lesson is about building an administrative interface that allows
> administrators to manage the application's data and features.
