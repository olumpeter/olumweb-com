## Step 1: Understand the Current Repetition 🔁

- Right now, protected routes look like this:


## Step 3: Create requireUserId() 🛡️

### Step 3a: Open auth.server.ts

- Open

```text
app/data/auth.server.ts
```

#### You already have this helper:

```ts
export async function requireUserId(request: Request) {
	const userId = await getCurrentUserId(request)

	if (!userId) {
		throw redirect('/login')
	}

	return userId
}
```

#### Important

- The application already has centralized authentication enforcement.
- This means:

  ```text
  Authentication rules already exist in one shared place
  ```

#### What this function actually does

- `requireUserId()` is responsible for enforcing authentication.

#### Step-by-step behavior

1. Route calls `requireUserId(request)`
2. Session gets checked
3. `getCurrentUserId(request)` reads authentication state
4. If no authenticated user exists:

- Execution stops
- Redirect to `/login`

5. If authenticated:

- Return `userId`

#### Mental Model

```text
Route → requireUserId() → Authentication Enforcement
```

#### Core Rule

```text
No authenticated user → No route access
```

#### Even Simpler

```text
Authenticated → Continue
Unauthenticated → Redirect
```

> Authentication enforcement now belongs to the authentication system itself

## Step 6: Understand getCurrentUserId() vs requireUserId() 🔍

#### Important Distinction

- `getCurrentUserId()`:

```text
Reads authentication state
```

- requireUserId():

```text
Enforces authentication
```

#### This distinction matters

- **Getter**

```text
Reads information
```

- **Require**

```
Enforces rules
```

- **Mental Model**

```text
Getter → Observation
Require → Enforcement
```

- **Reality**

```text
Is a user authenticated?
```

- Other times the application must enforce:

```text
This route requires authentication
```

- **Important**

```text
Reading state and enforcing rules are different responsibilities
```

> Good naming reflects system behavior clearly

## Step 7: Why throw redirect()? ⚡

#### Important

- Inside `requireUserId()`:

```ts
throw redirect('/login')
```

#### What this does

- Immediately stops execution.
- Prevents the route from continuing.
- Transfers control to the redirect response.

#### Mental Model

```text
Unauthenticated → Stop execution → Redirect
```

#### Why this matters

- The route should never continue running if authentication fails.

#### Reality

```text
Protection logic controls flow immediately
```

> Enforcement should stop invalid execution as early as possible
